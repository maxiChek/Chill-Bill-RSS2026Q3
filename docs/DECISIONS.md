# Решения и договорённости

Фиксируем важные решения и **почему** так. Один блок на решение. Статусы:
`принято` / `обсуждается` / `заменено`.

---

## Ванильный TypeScript + Vite, без UI-фреймворка

- **Решение:** чистый TS, DOM-хелперы вручную, без React/Vue/Lit.
- **Почему:** проект небольшой (5 экранов), быстрее стартовать, меньше зависимостей.
- **Статус:** принято.

## Без роутера

- **Решение:** переключение экранов in-memory (состояние экрана в памяти).
- **Почему:** URL-роутинг тут не нужен, не пилим лишнее.
- **Следствие:** экран не шарится ссылкой; F5 возвращает в начало приложения.
- **Статус:** принято.

## Landing отдельной страницей

- **Решение:** лендинг — статичный `index.html`; приложение — отдельный `app.html`
  (multi-page сборка Vite).
- **Почему:** не тащить лендинг в JS-бандл приложения.
- **Статус:** принято.

## Хранение — localStorage за интерфейсом репозитория

- **Решение:** доступ к данным только через `GroupRepository`, реализация — localStorage.
- **Почему:** логика и UI не знают, где лежат данные; смена хранилища — точечная.
- **Следствие:** контракт репозитория **синхронный** (бэкенд не планируется).
- **Статус:** принято.

## Деньги — целые числа в копейках

- **Решение:** `total`/`amount` — целые в копейках; в рубли форматируем при выводе.
- **Почему:** деление счёта порождает дроби; float даёт погрешность.
- **Статус:** принято.

## Остаток при делении поровну распределяем детерминированно

- **Решение:** при делении `total` на `n` остаток (`total mod n`) раздаём первым
  участникам по копейке; Σ долей строго == `total`.
- **Статус:** принято.

## Вычисляемое не храним

- **Решение:** в хранилище только группы/участники/операции; балансы и переводы
  считаем на лету.
- **Почему:** исключаем рассинхрон данных.
- **Статус:** принято.

## Подход к UI: сначала чистый HTML

- **Решение:** экраны сначала голым HTML без стилей; стилизация/адаптив/порядок —
  отдельным этапом; лендинг — последним.
- **Почему:** скорость разработки, фокус на функциональности.
- **Статус:** принято.
