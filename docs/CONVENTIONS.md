# Конвенции кода

## Общее

- Язык кода и коммитов — английский; UI-тексты, issues, описание PR — русский.
- Размер таба — 2 пробела, одинарные кавычки, точка с запятой. Форматирование —
  Prettier (`pnpm format`), линт — ESLint (`pnpm lint`).
- `strict: true`, `verbatimModuleSyntax: true` → типы импортируем через `import type`.

## Именование

- Интерфейсы/типы **без префикса `I`**: `GroupRepository`, `Group`, `Expense`.
- Файлы: `PascalCase.ts` для модулей с типом/классом-сущностью, `camelCase.ts` для
  утилит и функций. Внутри проекта придерживаемся единообразия по папке.
- Булевы — с `is/has/can`.

## Структура

```
src/
  models/types.ts     # модель данных (контракт)
  repositories/       # интерфейс + реализация хранилища
  domain/             # чистые функции: money, split, balances, settlement
  state/              # store + actions
  ui/                 # shell, навигация по экранам, экраны
```

- `domain/` — **чистые функции**: без DOM, без localStorage, покрыты тестами.
- Всё, что касается хранилища, — только в `repositories/`.

## Деньги

- Внутри — целые в копейках. В рубли конвертируем **только на выводе**.
- Никогда не работать с рублями как с float.

## DOM

- Не используем `innerHTML`
- Обработчики — через `addEventListener`.

## Состояние

- Единственный источник правды — store; изменения только через `actions`.
- Компоненты не мутируют состояние напрямую.

## Тесты

- Тесты кладём рядом с модулями

## Git

- Ветки: `feature/...`, `fix/...`, `chore/...`, `docs/...`.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`).
- Мелкие частые коммиты, один PR — одна задача.
- Как сливаем: Squash and Merge
- Ветки удаляются после слияния с main
- Merge делает ревьювер после апрува

## Обработка ошибок

- Все операции с внешними данными (localStorage, JSON.parse) оборачиваем в try/catch. Приложение не должно падать с белым экраном (White Screen of Death)
